# Контекст проекта и каретки в промпте модели: спецификация `flc-context/v1` (черновик)

Статус: черновик для ознакомления, 2026-10-09. Ничего из этого пока не реализовано ни в данных для обучения, ни в плагинах.
Документ общий для C# и Go: обозначения строк и правила одинаковые, языковые различия оговорены отдельно.

## 1. Что меняется и что нет

**Не меняется:**
- рантайм плагина (`ml-core`, `.cml`, нативные ядра), архитектура сети, токенизаторы `cs-16384.bpe` / `go-16384.bpe`;
- генерация: жадная, остановка на любом токене, который начинается с перевода строки; лечение токена (token healing),
  порог показа по произведению вероятностей, защита от повторов, обрезка закрывающих скобок.

**Меняется только промпт.** К нынешнему SPM-промпту добавляются два необязательных куска:
1. **Профиль проекта** `DEPS`: какие внешние библиотеки использует проект (Serilog или стандартный `ILogger`, zerolog или
   `log/slog`, xunit или NUnit, testify или стандартный `testing`).
2. **Блок фактов у каретки**: что видно в точке редактирования (тип результата функции, ожидаемый тип, параметры, локальные
   переменные, поля и методы текущего типа, тип получателя и его члены после `.`, перегрузки в списке аргументов, контракты
   ближайших типов проекта).

Оба куска необязательны: модель обучается и с ними, и без них (раздел 9). Плагин может включать и выключать их независимо.

## 2. Промпт целиком

Нынешний промпт движка (SPM):

```
<|fim_prefix|><|fim_suffix|>{суффикс}<|fim_middle|><|file_sep|>{путь}\n{префикс}
```

`flc-context/v1`:

```
<|fim_prefix|><|fim_suffix|>{суффикс}<|fim_middle|><|file_sep|>{путь}\n
[<|reserved_0|>DEPS {библиотеки}\n]
{префикс до конца предыдущей строки}
[<|reserved_1|>{строки фактов}<|reserved_2|>]
{\n + отступ + набранная часть текущей строки}
```

- `{суффикс}`, `{путь}` — как сейчас: текст после текущей строки (≤ 512 токенов) и путь файла относительно корня проекта.
- Строка `DEPS` стоит сразу после пути, до кода. Если профиля нет, её нет целиком (не пустая строка).
- **Блок фактов вставляется перед переводом строки, который открывает текущую строку**, а не после отступа. Так токены
  текущей строки (`\n` + отступ + набранное) получаются ровно такими же, как без блока: лечение токена и правило остановки
  не меняются. Если каретка на первой строке файла, блок стоит сразу после строки `DEPS` (или после пути).
- Если фактов нет (не удалось определить или выключено), блока нет целиком: ни `<|reserved_1|>`, ни `<|reserved_2|>`.
- Внутри блока строки разделяются `\n`; после последней строки перевода строки нет, сразу `<|reserved_2|>`.

Примеры ниже иллюстративные (сокращены, `…` — пропущенный код); точные эталоны будут в `fixtures/context/` (раздел 10).

### Пример (C#), каретка после `_logger.`

```
<|fim_prefix|><|fim_suffix|>
        await _orderRepository.UnitOfWork.SaveEntitiesAsync(cancellationToken);
        return true;
    }
}<|fim_middle|><|file_sep|>src/Ordering.API/Application/Commands/CreateOrderCommandHandler.cs
<|reserved_0|>DEPS MediatR Microsoft.Extensions.Logging Microsoft.EntityFrameworkCore FluentValidation
using MediatR;
…
        var order = new Order(request.UserId, request.UserName, address);<|reserved_1|>RET Task<bool>
ARG request:CreateOrderCommand cancellationToken:CancellationToken
LOCAL address:Address order:Order
FIELD _orderRepository:IOrderRepository _logger:ILogger<CreateOrderCommandHandler>
RECV ILogger<CreateOrderCommandHandler>
MEMBER LogInformation(string? message, params object?[] args)->void; LogWarning(string? message, params object?[] args)->void; BeginScope<TState>(TState state)->IDisposable?<|reserved_2|>
        _logger.
```
Ответ модели: `LogInformation("Creating order {OrderId}", order.Id);` и токен перевода строки.

### Пример (Go), каретка в начале пустой строки после проверки ошибки

```
…<|fim_middle|><|file_sep|>internal/store/orders.go
<|reserved_0|>DEPS github.com/rs/zerolog github.com/jackc/pgx github.com/stretchr/testify
package store
…
	if err != nil {<|reserved_1|>RET (*Order, error)
ARG ctx:context.Context id:int64
LOCAL row:pgx.Row err:error
FIELD db:*pgxpool.Pool log:zerolog.Logger<|reserved_2|>
		
```
Ответ модели: `s.log.Error().Err(err).Int64("id", id).Msg("load order")` — здесь профиль и поле `log:zerolog.Logger`
подсказывают zerolog вместо `fmt.Errorf`/`log.Printf`.

## 3. Служебные токены

Новые токены в словарь не добавляются. Используются уже зарезервированные специальные токены движка (в обоих словарях
`<|reserved_0|>` … `<|reserved_8|>` есть и не используются):

| Токен | Значение в `flc-context/v1` |
|---|---|
| `<|reserved_0|>` | начало строки профиля проекта (`DEPS …`) |
| `<|reserved_1|>` | начало блока фактов |
| `<|reserved_2|>` | конец блока фактов |
| `<|reserved_3|>` … `<|reserved_8|>` | свободны |

Как и остальные специальные токены, они никогда не получаются из текста: плагин вставляет их id напрямую
(`BpeTokenizer.specialId("<|reserved_1|>")`), текст строк фактов кодируется обычным `encodeBytes`.

## 4. Профиль проекта `DEPS`

**Что это.** До 12 корней внешних библиотек, которые использует проект, по убыванию числа файлов, где они встречаются.

**Как считать (C#).**
1. Взять все `using X.Y.Z;` / `global using X.Y.Z;` / `using static X.Y.Z;` / `using A = X.Y.Z;` из `.cs`-файлов проекта (для
   обучения — репозитория), **кроме текущего файла**.
2. Отбросить пространства имён, объявленные в самом проекте (`namespace …` в его файлах), и стандартную библиотеку:
   `System` и `System.*`.
3. Свести к корню:
   - `Microsoft.Extensions.*`, `Microsoft.AspNetCore.*` → три сегмента (`Microsoft.Extensions.Logging.Abstractions` →
     `Microsoft.Extensions.Logging`, `Microsoft.AspNetCore.Mvc.Routing` → `Microsoft.AspNetCore.Mvc`);
   - остальные `Microsoft.*`, `Google.*`, `Amazon.*`, `Azure.*` → два сегмента (`Microsoft.EntityFrameworkCore.Metadata` →
     `Microsoft.EntityFrameworkCore`, `Azure.Storage.Blobs` → `Azure.Storage`);
   - всё остальное → первый сегмент (`Serilog.Events` → `Serilog`, `MediatR` → `MediatR`, `Xunit.Abstractions` → `Xunit`).
4. Оставить корни, которые встречаются минимум в 2 файлах; отсортировать по числу файлов (убывание), при равенстве по имени.
5. Взять первые 12, записать через пробел. Строка не длиннее 200 символов (лишние корни отбрасываются с конца).

**Как считать (Go).**
1. Пути импорта из `.go`-файлов модуля, кроме текущего файла.
2. Отбросить стандартную библиотеку (первый элемент пути без точки: `fmt`, `net/http`) и пакеты самого модуля (префикс пути
   модуля из `go.mod`).
3. Свести к корню модуля: `github.com|gitlab.com|bitbucket.org|golang.org/x` → три элемента (`github.com/rs/zerolog/log` →
   `github.com/rs/zerolog`, `golang.org/x/sync/errgroup` → `golang.org/x/sync`); остальные хосты → два элемента
   (`go.uber.org/zap`, `gorm.io/gorm`, `k8s.io/client-go`); суффикс версии `/vN` отбрасывается.
4–5. Как в C#.

**Почему «кроме текущего файла» и «≥ 2 файлов».** Иначе библиотека, которую разработчик подключает прямо сейчас в редактируемой
строке, попадала бы в промпт из той же строки (утечка ответа), а единичные случайные импорты занимали бы место.

**В плагине** профиль считается по индексу проекта и кэшируется на проект. Пересчитывать его нужно при изменении импортов,
а не на каждое нажатие клавиши. Строка стабильна, стоит в начале промпта и не сбрасывает KV-кэш.

## 5. Блок фактов

### 5.1. Строки

Каждая строка: ключ, пробел, элементы. Порядок строк в блоке всегда такой, как в таблице. Пустые строки не выводятся.

| Ключ | Что | Элементы и формат | C# | Go |
|---|---|---|---|---|
| `RET` | тип результата охватывающей функции/метода/лямбды | `Task<bool>`, `(*Order, error)` | да | да |
| `EXPECT` | ожидаемый тип выражения у каретки — только когда он однозначно связан (аргумент с одним кандидатом, `return`, присваивание, инициализатор, условие) | `TimeSpan` | да | да |
| `ARG` | параметры в области видимости (метода, лямбды, primary-конструктора; в Go и получатель метода) | `имя:тип` через пробел | да | да |
| `LOCAL` | локальные переменные, объявленные **до** каретки и видимые в ней | `имя:тип` через пробел | да | да |
| `FIELD` | поля (и события/константы) текущего типа; в Go — поля получателя метода | `имя:тип` через пробел | да | да |
| `PROPERTY` | свойства текущего типа | `имя:тип` через пробел | да | нет |
| `METHOD` | методы текущего типа | `Имя(параметры)->Результат`, через `; ` | да | да |
| `RECV` | тип получателя после `.`, `?.` (C#), `.` (Go); `type X` — статический доступ, `namespace X` / `package X` — пространство имён/пакет | `ILogger<T>`, `type string`, `package time` | да | да |
| `MEMBER` | доступные члены получателя (все, а не только подходящие под набранное) | `Имя(параметры)->Результат` / `Имя:тип`; `+n` — ещё n перегрузок; через `; ` | да | да |
| `TYPE Имя:` | контракт ближайшего типа проекта (одна строка на тип, до 6 типов, до 10 членов) | `new(параметры)`, затем члены, через `; ` | да | да |
| `CALL` | перегрузки, применимые в текущей позиции списка аргументов | `сигнатура @индекс имя:тип`, через ` | ` | да | да |

### 5.2. Форматирование

- Типы — минимальные имена, как их написал бы разработчик в этой точке (`List<Order>`, а не `System.Collections.Generic.List<…>`;
  в Go — `pgx.Row`, `*Order`).
- Сигнатура метода: `Имя(тип имя, …)->Результат`; конструктор: `new(тип имя, …)`; дженерики как в исходнике.
- Идентификаторы с ключевыми словами экранируются как в языке (`@event`).
- Не более 24 элементов в строке; список обрезается с конца. Члены, уже использованные в видимом префиксе, идут первыми.

### 5.3. Бюджет и приоритет обрезки

Блок фактов не длиннее **192 токенов** (вместе с `<|reserved_1|>`/`<|reserved_2|>`). Если не помещается, строки допускаются по
приоритету, а внутри строки элементы обрезаются с конца:

`EXPECT` → `RECV` → `CALL` → `ARG` → `LOCAL` → `RET` → `MEMBER` → `FIELD`/`PROPERTY` → `TYPE` → `METHOD`

Порядок вывода при этом остаётся каноническим (таблица 5.1). Значение бюджета записывается в метаданные модели (раздел 8),
плагин обязан использовать то же значение.

### 5.4. Что плагин обязан соблюдать (иначе модель увидит не то, на чём училась)

- Факты считаются **по текущему состоянию документа**, без того, что правее каретки на текущей строке не набрано (в обучении
  это «снимок редактора»: хвост строки удалён). Код ниже текущей строки виден, как в редакторе.
- Переменная, которая объявляется на текущей строке (`var x = …` с кареткой внутри), в `LOCAL` не попадает.
- `MEMBER` и `CALL` — **все** доступные члены и все применимые перегрузки, без фильтрации по уже набранному префиксу имени и без
  угадывания «правильной»: модель учится выбирать сама.
- Заявленный nullable-тип выводится как заявлен; «доказанное не-null состояние» не выводится.
- Если тип получателя не определён (внешняя библиотека не разрешилась), строк `RECV`/`MEMBER` нет. Неполный блок лучше
  выдуманного.

## 6. Бюджет всего промпта

Окно модели — 2048 токенов. Распределение (в токенах токенизатора плагина):

| Часть | Лимит | Как сейчас |
|---|---|---|
| заголовок (`<|fim_*|>`, `<|file_sep|>`, путь) | по факту | так же |
| `DEPS` | ≤ 48 | — |
| факты | ≤ 192 | — |
| суффикс | ≤ 512 | так же |
| префикс | остаток, ≤ 1024 | так же |
| генерация | ≤ 48 | так же |

Если всё не помещается, сокращается префикс (с начала, по границе строки, как `InlinePrompt.stableTail`), а не факты и не суффикс.

## 7. KV-кэш

- `DEPS` и путь стабильны, суффикс стабилен, пока пользователь печатает в одной строке.
- Блок фактов стоит **после** всего префикса: при наборе в текущей строке префикс переиспользуется из кэша, а заново считаются
  только блок фактов и набранная часть строки (десятки–сотни токенов).
- При переходе на другую строку меняется граница префикса (как и сейчас), и блок пересчитывается.
- Если факты между нажатиями не изменились, блок совпадает побайтно, и кэш переиспользуется до набранной части.

## 8. Метаданные модели

В `meta` файла `.cml` добавляются ключи, по которым плагин понимает, что и как подавать:

```
contextFormat=flc-context/v1
contextDeps=reserved_0
contextFacts=reserved_1,reserved_2
contextFactsTokens=192
contextDepsMax=12
```

Модель без этих ключей — нынешняя: плагин подаёт старый промпт без `DEPS` и фактов.

## 9. Как модель учится переносить отсутствие контекста (обучающая смесь)

Чтобы модель не ломалась, когда плагин что-то не смог посчитать, обучающие документы — смесь:

| Доля | Документ |
|---|---|
| ~40 % | обычные файлы корпуса, как сейчас (plain + FIM SPM/PSM, без `DEPS` и фактов) |
| ~60 % | документы «на каретке» из наших сэмплов: SPM-промпт, ответ — остаток строки + перевод строки |
| из них ~70 % | с блоком фактов; в каждом блоке каждая строка независимо выбрасывается с вероятностью 15 % |
| из них ~30 % | без блока фактов |
| ~80 % всех документов | со строкой `DEPS` (если у репозитория профиль не пустой) |

Факты берутся из конфигурации `semantic` наших датасетов: посчитаны Roslyn (C#) и `go/types` (Go) на снимке без
недописанной части строки и прошли аудит утечек. Профиль считается по корпусу репозитория (раздел 4).

## 10. Эталонные примеры для тестов плагина (следующий шаг)

Будет файл `fixtures/context/golden-{csharp,go}.jsonl`, по одной позиции на строку:

```json
{"path": "src/A.cs", "source": "…текст файла с маркером ▮ на месте каретки…",
 "project_files": {"src/B.cs": "…", "src/C.cs": "…"},
 "deps": "DEPS MediatR Serilog", "facts": "RET Task<bool>\nARG request:CreateOrderCommand …",
 "prompt_tail": "…<|reserved_1|>RET Task<bool>\n…<|reserved_2|>\n        _logger."}
```

Плагин считает `DEPS` и факты для `source` (с соседними файлами `project_files`) и сравнивает с `deps`/`facts`. Полное
совпадение не обязательно: метрика — доля совпавших строк и элементов, отчёт по каждому ключу. Это и есть проверка того,
насколько анализатор плагина повторяет Roslyn/`go/types`.

## 11. Как будем проверять, что это вообще нужно

До доработки плагинов — замер на прокси-модели (31 M) на арендованной GPU:
1. Одна модель на смеси из раздела 9, оценка `eval_inline` на одних и тех же позициях в трёх режимах: без контекста, только
   `DEPS`, `DEPS` + факты.
2. Оценка на репозиториях, которых не видела ни одна модель (5–19 звёзд: ниже порога и корпуса движка, ≥ 20, и нашего, ≥ 35).
3. Разбивка по типу позиции: после `.`, в аргументах, начало строки, логирование, тесты.

Решение «делать в плагинах» — только если прирост заметен (ориентир: ≥ 1–2 п.п. «остаток строки точно» в целом или заметно
больше после `.`/в аргументах). Предыдущее измерение движка с Roslyn-контекстом другого вида (сигнатуры из других файлов)
дало около 2 %, так что результат заранее не очевиден.

## 12. Открытые вопросы

- Бюджет фактов: 192 токена — стартовое значение; подобрать по замеру (128 / 192 / 256).
- `TYPE`-строки дороже всего по токенам; возможно, лучше отдавать их только для позиций после `new`/в аргументах.
- Нужен ли `METHOD` (методы текущего типа) при наличии `MEMBER`: проверить абляцией.
- Для Go: стоит ли добавить `PKG` — экспортируемые члены пакета после `пакет.` (сейчас это `RECV package X` + `MEMBER`).
