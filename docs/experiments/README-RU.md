# Журнал экспериментов: модели дополнения строк C# и Go для плагинов IDE

Хронология решений, экспериментов и результатов: от датасета до моделей, готовых для плагина. Цифры взяты из
машиночитаемых отчётов в `data/` (ссылки в каждом разделе); примеры генераций — в `samples/`. Документ ведётся по мере работы:
новые эксперименты дописываются в конец с датой.

## 0. Задача и ограничения

- **Продукт:** inline-подсказка «остаток текущей строки» (full-line code completion) в плагинах IntelliJ для C# (Rider) и Go.
- **Движок плагина:** собственный `ml-core` (Kotlin + нативные int8-ядра, формат `.cml`), без внешних рантаймов. Модель —
  decoder-only трансформер в стиле Llama (RMSNorm, RoPE, GQA, SwiGLU, tied embeddings), контекст 2048, BPE 16 384
  (`cs-16384.bpe` / `go-16384.bpe`). Промпт — SPM-FIM: `<|fim_prefix|><|fim_suffix|>суффикс<|fim_middle|><|file_sep|>путь\nпрефикс`.
- **Размер модели:** 50M параметров (`go50m`: d640 × 10 слоёв, 10 голов, 2 KV-головы, FFN 1536; 49.8M, `.cml` 50 МБ) —
  предел по задержке на ноутбуке пользователя.
- **Отправная точка:** модели движка `cs-nn-50m-e3-lr2e3` и `go-nn-50m-e3-lr2e3`, обученные на ~5.65 / 6.85 млрд токенов
  (репозитории GitHub с ≥ 20 звёздами) без отдельного дообучения на задачу.
- **Бюджет:** арендованные GPU по часам — каждое решение проверялось сначала дёшево (CPU, короткие прогоны).

## 2. Эксперимент 01 — блок контекста на готовой модели (2026-10-09/10)

**Вопрос:** помогает ли блок контекста (`flc-context/v1.1`: профиль зависимостей + факты RET/EXPECT/ARG/LOCAL/FIELD/
PROPERTY/RECV/MEMBER/CALL перед текущей строкой) — до того, как дорабатывать плагины.

**Схема:** готовая модель плагина C# 50M, дообучение на 311 тыс. позиций каретки в двух вариантах — с контекстом (A) и без (B),
одинаковые документы и порядок; 2× RTX PRO 6000, по варианту на карту, ~1 ч. Оценка на 12 000 чистых позиций, парный бутстрап.

| C#, 12 000 позиций | Строка целиком | Показ | Точность показанных |
|---|---|---|---|
| Готовая модель плагина | 32.9 % | 15.4 % | 80.9 % |
| B: дообучение без контекста | **39.5 %** | 25.0 % | 87.8 % |
| A: с контекстом, промпт без контекста | 39.1 % | 25.0 % | 88.4 % |
| A: с контекстом, полный блок | 38.6 % | 24.0 % | 88.4 % |

**Выводы.**
1. Дообучение на задаче (позиции каретки, loss только на ответе) — **+6.6 п.п.** (95 %: +5.8…+7.4).
2. Блок контекста — **без пользы** (−0.95 п.п. с фактами, 95 %: −1.5…−0.4). Разбор примеров: правильный член часто не попадал в
   список `MEMBER`, обрезанный бюджетом токенов; `METHOD`/`TYPE` были исключены в v1.1; остальные факты повторяют видимый код.
3. **Решение:** доработку плагинов под контекст не делать; дальше — данные и обучение без контекста.

Файл: `data/01-context-ab-shipped-model/report.json`.

## 3. Решение: обучение с нуля на своих данных (2026-10-10)

Корпус расширен (раздел 1) до объёма движка и больше, поэтому обе модели обучены **с нуля** по рецепту движка, затем дообучены
на позициях каретки.

- **Обучение языку:** `train.py` движка, `go50m`, AdamW (0.9, 0.95), wd 0.1, lr 2e-3 → 2e-4 (косинус, разогрев 500),
  0.5 млн токенов на шаг, FIM 0.7 / SPM 0.5, bf16 + `torch.compile`, 1 эпоха (C# 12 343 шагов, Go 19 876).
- **Железо:** C# — 2× H200 NVL (DDP), 1 ч 13 мин, 1.58 млн токенов/с. Go — H100 NVL (0.67 млн ток/с) → перенос чекпоинта на
  одну H200 (0.84 млн) → на две H200 (1.59 млн) с конвертацией состояния потока данных под 2 ранга (`ckpt_to_ranks.py`,
  продолжение без повторов и пропусков).
- **Промежуточное качество:** каждые 5000 шагов — замер на 2000 чистых позициях (`ckpt_eval_loop.sh`).

| Модель только после обучения языку (12 000 позиций) | Строка целиком | Показ | Точность |
|---|---|---|---|
| C#: готовая модель плагина / **новая** | 32.7 % / **33.5 %** | 15.4 % / 15.8 % | 81.3 % / 80.8 % |
| Go: готовая модель плагина / **новая** | 34.8 % / **36.0 %** | 21.5 % / 21.7 % | 80.9 % / 82.3 % |

Новые модели уже без дообучения не хуже готовых (C# +0.7, Go +1.2 п.п., оба значимы). Файлы: `data/02-csharp-first/`,
`data/05-go/report-base.json`, кривые обучения `*/pretrain.metrics.jsonl`.

## 4. Эксперимент 02 — первое дообучение C# (lr 2e-4)

Рецепт эксперимента 01 (lr 2e-4, 1.05 млн позиций, 1 проход): **40.5 %** строк целиком (+7.8 п.п. к готовой модели), показ 25.0 %,
точность 89.9 %. Странность: loss дообучения рос с ~0.78 до ~1.07 — разобрана в эксперименте 03. Файл: `data/02-csharp-first/report.json`.

## 5. Эксперимент 03 — разбор loss дообучения

- Гипотеза «модель запомнила обучающие файлы» **отвергнута**: loss на обучающих и невиденных позициях одинаков (1.19 / 1.19).
- Причина низкого старта — **стоп-токен**: модель, обученная на целых файлах, никогда не видела `<|endoftext|>` сразу после строки
  (loss 3.6 на 10 % токенов ответа); дообучение выучивает его за ~100 шагов.
- Рост потом — ухудшение на самих строках: при ~300 токенах ответа в шаге градиенты шумные, и lr 2e-4 «размывает» модель.

Файл: `data/03-finetune-loss-probe/report.json`.

## 9. Что сработало и что нет (для доклада)

1. **Дообучение на задаче плагина** — главный источник прироста (C# +8…+10, Go +16 п.п. сверх обучения языку): тот же формат
   промпта, что у плагина, loss только на остатке строки + стоп-токен.
2. **Шаг дообучения** — маленький (5e-5) лучше «обычного» (2e-4) на 3.3 п.п.; loss дообучения обманчив (стоп-токен в начале,
   рост loss при улучшении качества) — решения принимались только по качеству на чистых позициях.
3. **Свои данные с нуля** — на уровне модели движка уже до дообучения, при честной изоляции проверки.
4. **Блок контекста (факты о переменных/членах) — не помог** в формате v1.1; помочь может только информация, которой нет в
   видимом коде (сигнатуры типов из других файлов), — отдельная гипотеза (раздел 11).
5. **Методика:** чистый проверочный набор из невиденных репозиториев, парный бутстрап, промежуточные замеры каждые
   4–5 тыс. шагов, дешёвые короткие прогоны перед дорогими.

## 10. Инциденты и уроки

- Отклонённая пользователем команда на сервере иногда всё-таки успевала выполниться — после каждого отказа проверялось
  состояние серверов.
- `pkill -f <шаблон>` внутри `ssh '…'` находит собственную команду и убивает её — останавливать процессы по PID.
- Воркеры `torch.distributed.run` живут в своей сессии: после переноса Go на две карты старый одиночный процесс час учился
  параллельно на второй карте (скорость упала вдвое). Проверять `nvidia-smi --query-compute-apps`.
- Два оркестратора на одной базе состояния сбрасывают задачи друг друга (`running → pending`): ~520 репозиториев
  переобработаны.
- Нехватка видеопамяти при оценке рядом с двумя дообучениями — пересчёт с маленьким батчем.

## 11. Следующие шаги

   + сигнатуры типов из других файлов в промпте; сначала дешёвая проверка покрытия на CPU.
3. Модель 100M — если плагин укладывается по задержке.
